Sources

The R6RS version of steinmetz is on GitHub. In addition to the R6RS standard libraries, it depends on SRFIs 1, 115, and 152. SRFI 64 is required to run the included tests.

Using steinmetz

There are three libraries of general utility:

(steinmetz parse)

Exports the two primary parsing procedures and the high-level option-definition forms. For simple programs, this is all you’ll need.

(steinmetz options)

Exports the low-level option interface.

(steinmetz usage)

Exports display-usage, a procedure for printing formatted usage information drawn from a set of options.

(steinmetz command-line) is available but probably not very interesting. It provides a command-line pre-processor which is used by the parsing procedures.

Option type

Command-line options are described by the Option type. The high-level syntactic interface to creating Options will be described first, followed by the high-level procedural interface, and then finally the lower-level core procedures exported by (steinmetz options).

Syntactic interface

(options clause …) → (list Option)

The options form is a convenient interface to the options library. Each clause describes a single option and is of one of the following forms:

(flag name-or-names [docstring])
(option name-or-names [arg-spec [docstring]])

The (flag …) form describes a boolean flag which takes no arguments; (option …) describes an option taking an argument. name-or-names is either a string, an identifier, or a list of strings or identifiers, and gives the acceptable forms of an option (with leading dashes omitted). docstring-text is a string describing the option. arg-spec describes the option’s argument and takes one of the following forms:

arg-name
(arg-name default)
(arg-name default (enum …))
(arg-name default conv)

arg-name is an identifier giving a metalinguistic name for the argument. default is an expression whose value is used as the value of the argument if the option is omitted. (If the option is present, an argument is still mandatory.) If the final component of an args-spec is of the form (enum …), where each enum is an identifier or string, then these describe the only allowed values of an “enumerated” argument. Otherwise, the final component must be an expression evaluating to a procedure. The resulting procedure is the converter (see make-cli-option) of the new option.

Rationale: In this simplified interface, argument converters and enumerated arguments are treated as mutually exclusive. Converting symbolic names to non-string values doesn’t seem useful enough to justify additional syntax.

Note

Option names and allowed arguments may be written as identifiers for convenience, but will be stored as strings in the actual Option objects. For example,

(map option-names (options (flag (v verbose))))
  ⇒ (("v" "verbose"))

The acceptable command-line form of each name is determined by its length. A single-character name like o will be parsed as a “short” option, i.e. -o, while a two-or-more-character name like output will be parsed as a “long” option, i.e. --output. See Parsing conventions below for more details on how options and their arguments are parsed.

The value of an options form is a list of option structures representing the CLI options described by its clauses.

Example

(define my-opts
  (options
   (option (f file) (FILE "-") "input file")
   (option (k chunk) (NUM 0 string->number) "chunk to operate on")
   (option (e) (ENDIANNESS "big" (big little)) "stream endianess")
   (flag (v verbose) "verbose output")
   (flag ("1") "a numeric option")))

Procedural interface

High-level

These procedures are exported by (steinmetz parse). They automatically generate parsers and fill in details which users of the (steinmetz options) interface must provide explicitly.

(make-cli-option names [arg-name [conv-proc [properties]]]) → option

Argument types:

names
A list of strings
arg-name
A symbol or #f.
conv-proc
A procedure taking a single string and returning a single value.
properties
A symbol-keyed association list.

Returns an Option object describing a command-line option.

names gives the command-line forms of the option, with leading dashes omitted.

If arg-name is provided, the command-line option will take a (single) required argument. If it is false, the option will not take an argument (and its parser will raise an exception if an argument is provided).

If conv-proc is provided, it must be a procedure which accepts a single string argument and returns a single value. conv-proc is applied to the value of the option’s command-line argument. conv-proc defaults to values.

If properties is provided, it must be a symbol-keyed alist. Any number of arbitrary properties may be added. (See also Common properties below.) properties defaults to an empty list.

The parser generated by make-cli-option will associate a name of the option with the value of (conv-proc arg), where arg is the option’s command-line argument, if the option is encountered at all.

(make-cli-flag names [properties]) → option

A restricted version of make-cli-option for creating “flags”, options which take no arguments and are merely present or absent. names and properties have the same types and meanings they do for make-cli-option.

The parser generated by make-cli-flag will associate a name of the flag with #t, if the flag is encountered at all.

Common properties

The following properties are used by various parts of the steinmetz package:

docstring

The associated value is a string describing the option.

default-argument

An arbitrary value used as the value of an option’s argument whenever that option is omitted.

allowed-arguments

A list of strings giving the set of valid arguments for an option.

canonical-name

A string giving an option’s preferred name. This is useful for options that have multiple names. The canonical name need not be one of an option’s “public” names.

Core procedures

(make-option names argument-name argument-parser properties) → option

Argument types:

names

A list of strings.

argument-name

A symbol or #f

argument-parser

A procedure that accepts a single string-list argument and return two values: the value of the option’s argument and a suffix of the list argument. An argument parser should signal a parser exception if its input list is invalid. For example, the following is a valid parser:

(lambda (tokens)
  (if (null? tokens)
      (parser-exception "missing argument" tokens)
      (values (car tokens) (cdr tokens))))
properties

A symbol-keyed association list.

Returns a new Option with fields determined by the arguments.

(option-names option) → (list string)

Returns a list of the accepted names of option.

(option-argument-name option) → (or symbol #f)

Returns the symbolic name of option’s argument.

(option-argument-parser option) → procedure

Returns the argument parser associated with option.

(option-properties->alist option) → (alist symbol *)

Returns the properties mapping of option as a symbol-keyed alist. Mutating this alist causes undefined behavior: it may or may not be option’s internal representation of its properties mapping.

(option? obj) → boolean

Returns #t if obj is an Option and #f otherwise.

An Option’s property mapping can be manipulated with the following convenience procedures.

(option-get-property option key) → *

Returns the value associated with key (a symbol) in option’s property mapping. If no association exists, returns #f.

(option-set-property option key obj) → option

Returns a copy of option with a new property association of key to obj. Any existing association for key is replaced.

Parsing

Parsing conventions

A single option may have multiple “short” (single-character) and “long” (two-or-more-character) names. Following tradition (and POSIX), short options without arguments followed by a single option that may take an argument can be run together. For example, -ab is equivalent to -a -b if the -a option takes no argument. The argument of a short option is either the next token, or the rest of the option string. e.g. -ab is equivalent to -a b (option a, argument b) whenever the -a option takes an argument. (The distinction between option clusters and short options with run-in arguments is clear but rather subtle.)

For a long option, the argument is the next token unless an argument was supplied as part of the option token, with the two components being separated by an = character. For example, --output=foo.log is equivalent to --output foo.log.

Note that “X Windows–style” long options with a single leading dash (e.g. -output) are not supported, since they conflict unavoidably with short-option clusters. Optional arguments complicate cluster analysis, but they might be supported at some later date.

The first non-argument occurrence of -- terminates option parsing. All remaining tokens are treated as arguments.

Procedures

(parser-exception message irritant …)

Raises a continuable exception indicating that something went wrong during command-line parsing. message must be a string. The irritants may be anything. In the R6RS version of steinmetz, the raised object is a compound condition satisfying parser-condition? and including (at least) &message and &irritants components.

(parser-condition? obj) → boolean

True of obj is a condition raised by parser-exception.

(process-command-line options [cl-list]) → [alist, list]

A easy-to-use high-level parsing procedure. options is a list of Option objects. Parses cl-list (a list of strings, or the value of (cdr (command-line)) by default) and returns two values: an alist associating the name of each option encountered (as a string) with a list of arguments, and a list of tokens unassociated with any of the options (the “operands”). The order of cl-list is preserved in the operand list and in each option’s argument list, but the order of the options-and-arguments alist is unspecified.

For the keys of the alist return value, process-command-line uses the value of each option’s canonical-name property. If an option lacks this property the first element of the option’s names list is used.

If an unknown option is encountered while parsing, an object satisfying parser-condition? is raised continuably.

Example

(let ((opts (options
             (option (f) FILE "input file")
             (flag (v) "verbose output")))
      (cl '("-f" "file1" "-v" "-f" "file2" "frobnitz")))
  (process-command-line opts cl))

⇒ (("v" #t) ("f" "file1" "file2"))
  ("frobnitz")

If an option has the allowed-arguments property and its associated value is a list of strings, then only arguments from that list will be considered valid. Others will raise parser exceptions. (The test is done before an option’s argument converter is applied to the argument string.)

Example

(let ((opts
       (list (make-option '("e" "endianness")
                          'ENDIANNESS
                          string->symbol
                          '((allowed-arguments "big" "little")
                            (canonical-name . "endianness"))))))
  (parse-command-line opts '("-e" "little" "foo"))
  ; ⇒ (("endianness" "little")) ("foo")
  (parse-command-line opts '("-e" "medium" "foo")))
  ; parser exception: invalid argument "medium"

FIXME: Flags aren’t treated specially at the moment, so n appearances of a single flag will result in a list of n #t values.

(parse-command-line options proc cl-list seed …) → *

Argument types:

options
A list of Options.
proc
A procedure as described below.
cl-list
A list of strings.
seed
An arbitrary value.

A general-purpose parsing procedure similar to SRFI 37's args-fold. Applies proc to options and arguments derived from cl-list. At each step, proc is applied to an Option, the option's argument value (or #f if the option has no argument), and the current seeds. For example, if the first two elements of cl-list are "-f" and "foo", then proc will be invoked as (proc f-opt "foo"), where f-opt is the Option whose names include f. proc is expected to return one or more values, the first of which is interpreted as a boolean indicating whether to keep parsing: if it is false, parse-command-line halts immediately, returning the current seeds and the remaining suffix of cl-list as multiple values.

The seed arguments are used as the initial seeds, and the remaining values returned by proc (those after the “keep parsing?” boolean) are used as the seeds for the next step.

If a token is encountered which is not an option or an option’s argument, it is passed as the second argument to proc, and proc’s first (option) argument will be #f. For example, if the first element of cl-list is "frob", then proc will be invoked as (proc #f "frob").

parse-command-line returns the values returned by the final invocation of proc, followed by the remaining suffix of cl-list.
